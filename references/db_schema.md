# 素材数据库：字段和打分标准

数据库是整个流程的地基。后面的故事方案、剪辑表、找镜头，全都从这张表里查，所以每一行都要写到「不回去看视频也知道这段能怎么用」。

## 存放方式

- 每天一个文件：`analysis/db/day_YYYYMMDD.jsonl`，每行一个 JSON 对象 = 一个片段。
- 一个原片可以拆成好几行：一段 10 分钟的视频里先在吃饭、后来在街上走，就拆成两行，用 `start`/`end` 标出各自的时间范围。拆分的原则是「事件变了」，不是固定时长。
- 写完一天就运行 `db_export.py`：它会检查格式、导出 Excel 能打开的表，并提示还有哪些原片没建档。

## 字段

| 字段 | 类型 | 写什么 | 例子 |
| --- | --- | --- | --- |
| `id` | 文本 | `片段ID@开始时间`，全库唯一 | `DJI_0053@02:05` |
| `file` | 文本 | 片段 ID（原片文件名去掉扩展名） | `DJI_20260927203356_0053_D` |
| `start` / `end` | 文本 | 这一行覆盖的时间范围 `mm:ss` | `02:05` / `03:00` |
| `date` / `clock` | 文本 | 拍摄日期、时刻（文件名或元数据里有） | `2026-09-27` / `20:33` |
| `place` | 文本 | 地点；不确定写「（推测）」 | `火车街：相机放在铁轨上` |
| `people` | 列表 | 画面里或说话的人；路人写「路人」 | `["A", "C"]` |
| `visual` | 文本 | 画面里有什么，一句话 | `低角度：车头驶来，车底从头顶掠过` |
| `event` | 文本 | 发生了什么事，一句话 | `火车从相机正上方开过` |
| `quotes` | 文本 | 值得用的原话，用 ` / ` 分隔；**照转写原文抄，不改写** | `刚好拍到 / 太好了` |
| `reaction` | 文本 | 人物反应 | `欢呼`、`笑场`、`尖叫` |
| `mood` | 文本 | 情绪 | `震撼`、`释放/开心` |
| `funny` / `story` | 布尔 | 好不好笑 / 有没有故事 | |
| `broll` / `transition` | 布尔 | 能不能当空镜 / 转场 | |
| `opener` / `ending` | 布尔 | 能不能当开头 / 结尾 | |
| `video_q` / `audio_q` | 1–10 | 画面、声音质量（糊、抖、风噪大就低） | |
| `score` | 对象 | 七项 1–10 分，见下 | |
| `grade` | 文本 | S / A / B / C | |
| `tags` | 列表 | 方便以后搜的词 | `["火车", "开场"]` |
| `notes` | 文本 | **最重要的一栏**：伏笔、呼应、能接在哪、待确认的事 | `开场首选；『上头了』可以接在火车镜头后面` |

`score` 的七项：`person`（人物）、`story`（故事）、`funny`（笑点）、`emotion`（情绪）、`visual`（画面）、`rarity`（稀缺，这辈子还能不能再拍到）、`overall`（综合）。

## 打分的优先级：人物 > 故事 > 情绪 > 景色

这是一支给自己和朋友看的片子，大家多年后想看的是彼此的样子和那些好笑的瞬间，不是风景。一个漂亮的空镜，比不上朋友笑到岔气的五秒。所以：

- 画面一般但人物鲜活、有梗、有反差 → 可以给 S。
- 画面很美但没人、没事 → 一般是 B（空镜够用就行）。
- 误录、口袋里录的、重复的、黑屏 → C。

## 等级的大致比例

参考一次 13.7 小时、390 个片段的旅行：S 35（9%）/ A 90（23%）/ B 181（46%）/ C 84（22%）。

- **S**：必用。整趟旅行的高光，剪掉会可惜。
- **A**：很可能用。好笑、有信息量、能撑起一个段落。
- **B**：备用、过场、空镜。
- **C**：基本不用。

S 级如果超过 15%，标准大概松了；低于 5%，可能漏看了好东西。

## 备注栏怎么写

备注是后面写故事方案时最有用的东西。看到这些就记下来：

- **伏笔和呼应**：同一句话、同一件事隔几天又出现（「下次不来了」第一次在大教堂说，晚上在火车街又说了一遍）。记下两边的 `id`。
- **反差**：说怕高的人后来玩得最疯；第一天说「好混乱」，后来说「终于有点来旅游的意思了」。
- **能接在哪**：「这句可以接在上一个镜头后面」「适合当某一章的开头」。
- **待确认**：认不准是谁、听不清说了什么、转写可能有误。写清楚，留给用户确认，不要猜。

## 不编造

转写只是机器听写，经常出错，尤其是外语、方言、人多嘴杂、有背景音乐的时候。

- `quotes` 只抄转写里的原文。转写明显是乱码或幻听（见避坑清单第 1、2 条），就不要抄进来。
- 关键台词（要上字幕、要当梗用的）先用 `transcribe.py --recheck` 不带提示词重听一遍，确认后再用。
- 认人只依据用户告诉你的特征。认不准就写「待确认」，不要猜名字。
