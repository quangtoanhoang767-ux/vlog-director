# 审片反馈 → 该怎么改

用户通常不懂剪辑术语，会用感受来描述问题。下面是真实项目里出现过的说法和对应的改法。

| 用户说 | 实际问题 | 改法 |
| --- | --- | --- |
| 「太长了」「再短一点」 | 节奏拖 | 先砍 B 级镜头和重复的同类镜头，再缩短每个镜头的头尾；不要先砍 S 级 |
| 「开头和正片重复了」 | 同一镜头用了两次 | 正片里换角度或换时间段（避坑 7） |
| 「音乐别比人声大」 | 对白时配乐太响 | 降低说话档（-34 → -37 dBFS），检查笑声是否被检测到 |
| 「BGM 时大时小」 | 闪避太灵敏 | 确认是两档固定音量、2.5 秒内的空隙已填平（避坑 3）；不要改成更复杂的动态处理 |
| 「音乐可以多一点」 | 纯音乐镜头太少 | 增加空镜、过场，或把部分对白镜头改成 `BGM` |
| 「这段删掉」 | — | 直接删，顺便检查删掉后前后两个镜头接得是否自然 |
| 「这是哪个镜头」（发截图） | 要定位素材 | 看截图内容，用 `find.py` 搜台词、或查数据库 `visual` 字段，报出片段 ID、时间和原片路径 |
| 「把 X 镜头放进去」 | 有必须要的镜头 | 先用数据库和 `find.py` 找到，确认是哪一段再放；放在哪由你按故事安排，并说明理由 |
| 「炫酷一点」 | 想要节奏感和动效 | 推荐混剪模式 |
| 「就这版了」 | 定稿 | 记下定稿的剪辑表版本号和成片路径；提醒中间文件可以清理（见 SKILL.md 收尾） |

## 每次改完要告诉用户

1. 改了什么（对应他说的哪一条）。
2. 新成片的路径。
3. 有没有顺带改动别的地方。

用户只需要看片子，不需要看剪辑表。
